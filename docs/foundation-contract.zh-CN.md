# 职责与安全规则

[English](foundation-contract.md)

本文说明通用工具与每个生成应用之间的约定。添加自定义编译目标、发布文件或运维命令时，
本说明最有帮助。

## 支持环境

0.6 版本测试过的生产环境如下：

- Ubuntu 24.04 x86-64；
- GCC 13 和 C++20；
- 使用 Clang 18 做额外兼容与代码分析检查；
- CMake 3.21 或更高版本、Ninja 和 Conan 2.8.1；
- GitHub Actions `ubuntu-24.04` runner；
- 命令行工具使用 Python 3.11 或更高版本。

其他系统可以用于开发，但在作为生产环境前，需要单独完成编译和运维验证。

## 每个项目必须提供什么

1. 一个服务程序的 CMake 目标；
2. 一个已经注册到 CTest 的测试目标；
3. 一个 Conan profile 和项目自己维护的 lockfile；
4. 至少一个放入发布归档的程序；
5. 服务不健康时会失败的 `verify` 命令；
6. 启用可选 canary 和性能任务前，提供应用自己的对应命令。

这些名称和命令记录在 `foundation.toml` 中。

## 运维命令规则

部署期间，运维命令会在解压后的发布目录中运行，并通过 `FOUNDATION_RELEASE_DIR` 获得
该目录路径。

命令应允许安全重试。例如，重复启动已经运行的服务或停止已经关闭的候选版本，都不应
破坏数据。

不要在 `foundation.toml`、命令参数、发布文件或 JSON 摘要中保存凭据。运行时应从主机
管理的密钥存储或受保护环境中读取。

## 发布安全规则

- 打包只使用一个干净、已经审核的 Git 提交；
- 每个运行时文件都会记录大小、可执行设置和 SHA-256；
- 部署安装时必须另外提供归档校验文件；
- 额外文件、缺失文件、链接和不安全路径都会被拒绝；
- 软件清单必须与实际发布文件一致。

稳定的运行时摘要可以帮助比较两次编译。由于完整归档会记录编译时间和 runner 信息，
它们的所有字节仍可能不同。

## 运维记录规则

- 记录只新增，不会悄悄替换已有记录；
- 被引用的摘要会复制到根据文件内容生成的名称下；
- 验证会拒绝内容变化、不安全路径、链接、特殊文件和 evidence 目录中的无关文件；
- 只有另一台主机或存储系统已经复制并验证，本地 evidence 包才算安全保留。

## 本工具不承诺什么

- 不实现应用协议、数据库或服务发现；
- 不证明多主机高可用或灾难恢复；
- 不决定生产容量或允许的响应时间；
- 不在无关项目之间共享同一个依赖 lockfile；
- 不自动部署未审核分支；
- 不通过降低限制或忽略失败来让编译通过。
